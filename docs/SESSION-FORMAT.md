# fieldtap-session/1: the session format

A FieldTap session is a directory of seven files. The laptop tool writes it, the Android app
"5gto6G FieldTap" writes it, and `fieldtap report <dir>` renders it. This document is the
contract for anything other than the fieldtap Python package that writes one, starting with the
app's Kotlin writer.

Three things back it up, and they win over this prose if they ever disagree:

- [`schema/columns.json`](../schema/columns.json) is the authority for every column list,
  column type, numeric format, allowed value and limit, and for the byte rules a code generator
  needs: rounding, digits, quoting, line breaks and how a `pattern` matches (its `encoding` and
  `patterns` keys). The Kotlin constants are generated from it. It is `fieldtap.contract.schema()` written out, and `tests/test_android_session.py` fails
  when the two differ.
- [`tests/fixtures/android_session/`](../tests/fixtures/android_session/) is the golden session.
  The Kotlin `:format` tests must reproduce its CSV files byte for byte. It is generated by
  [`tests/fixtures/make_android_session.py`](../tests/fixtures/make_android_session.py) using
  fieldtap's own writers.
- `fieldtap validate <dir>` checks a session against this contract (see
  [fieldtap validate](#fieldtap-validate)).

Every rule below says what breaks when it is violated. "Crashes" means `fieldtap report` stops
with a Python exception and produces no report. "Silently" means the report renders but is wrong.

---

## At a glance

```
20260910-143000_Mall-walk-north-path/      <yyyyMMdd-HHmmss of started_utc>_<slug of name>
  session.json     what, when, which phone, how well sampled        always
  kpi.csv          one row per fresh serving-cell sample per RAT     always (header row at least)
  track.csv        GPS fixes                                         left out at location precision "none"
  events.csv       cell changes, markers, gaps, failures             always (header row at least)
  traffic.csv      ping and download results                         always (header row at least)
  cells.csv        one row per serving cell                          always (header row at least)
  cellinfo.csv     every cell of every cell-info answer, raw         always (header row at least)
```

The app never writes `summary.json`, `report.html` or `index.html`; `fieldtap report` does, and
they are never uploaded.

## Rules shared by every file

### Encoding

| Rule | What breaks otherwise |
| --- | --- |
| UTF-8. | A file that is not UTF-8 makes the report's reader raise `UnicodeDecodeError`: crashes. |
| No byte order mark (no `EF BB BF` at the start). | In a CSV the first header becomes `\ufefftime_utc`, so `row["time_utc"]` finds nothing: `track.csv` crashes the report (`KeyError`), `events.csv` silently loses every event time. In `session.json`, `json.load` refuses the file: crashes. |

### CSV bytes

These are the bytes Python's `csv` module writes with its default dialect, which is how
fieldtap writes every CSV. A Kotlin writer that follows them reproduces the golden files exactly.

| Rule | Detail | What breaks otherwise |
| --- | --- | --- |
| Line ending CR LF | Every line, the header and the last row included, ends in `\r\n` (0x0D 0x0A). Python's csv writer uses `\r\n` on every platform. Kotlin's `appendLine` and `println` write `\n` alone, so write `\r\n` explicitly. | The report reads LF too, but the golden-file comparison fails, and the cut-back on the next launch (see [Writing safely](#writing-safely)) drops every row after a line that ends in LF alone. `fieldtap validate` warns, naming the first such line. |
| Header row always | The exact header from `columns.json`, even when there are no data rows. | A renamed, missing or reordered column: the readers look columns up by name, so `track.csv` without `lat` crashes (`KeyError`) and `kpi.csv` without `rsrp_dbm` silently has no RSRP. |
| Delimiter | `,` with no spaces around it, and none after the last field. Every row has exactly as many fields as the header, so a row whose last field is blank still ends in a comma before the line ending: `...,no fresh cell info for 14.0 s,,,,screen_off,\r\n`. | A row with fewer fields gives `None` values: `track.csv` crashes (`float(None)`). `fieldtap validate` rejects it. |
| Quoting | A field is enclosed in `"` only if it contains a comma, a `"`, a CR or a LF (`encoding.csv_quote_if_contains`). A `"` inside it is doubled (`""`). Nothing else is quoted: not numbers, not blanks, not text without those characters. | An unquoted comma shifts every later column of that row. |
| Line breaks in text | Free text (titles, details, notes, errors) is written with CR and LF replaced by a space (`encoding.text_line_breaks`). | Python would quote it and read it back, but the record then spans two physical lines, which breaks line numbers, `diff`, any line-based tool and the cut-back on the next launch. `fieldtap validate` warns. |
| Blank means unknown | An unknown value is an empty field: two adjacent commas. Never `null`, `NaN`, `N/A`, `""`, `2147483647` or `-2147483648`. | `2147483647` is Android's "unavailable": written as a value it becomes +2147483647 dBm in an average. `null` or `NaN` in a numeric column crashes the reader (`float("null")`) or poisons an average. |
| No blank lines | Not between rows and not at the end. | Ignored by the readers, reported by `fieldtap validate`. |

The one CSV value that looks like a placeholder but is not: `rat` in `events.csv` is `-` for a
row that is not about a radio (a marker, a GPS event, a sampling gap).

### Numbers

`columns.json` gives every numeric column a `type`, a `format` and, for decimals, `decimals`. The
`format` is the Python reference for the digits. It is never a format string for `String.format`
or `java.util.Formatter`, which round differently (see below). `encoding` in `columns.json` holds
the same rules as data: `number_rounding` `half_even_exact_binary`, `number_digits` `ascii`,
`decimal_separator` `.` and `negative_zero` false.

| Type | Written as | Python reference | Kotlin |
| --- | --- | --- | --- |
| `integer` | Optional `-`, then digits, no leading zeros, no `+`, no decimal point, no grouping. | `"%d" % v` | `v.toString()` on an `Int` or `Long` |
| `decimal` with `decimals` N | Optional `-`, at least one digit, `.`, exactly N digits. | `"%.Nf" % v` | `BigDecimal(v).setScale(N, RoundingMode.HALF_EVEN).toPlainString()` |

- `"%.Nf"` rounds the exact binary value of the double, ties to even. `BigDecimal(v)` (the
  double constructor, not `BigDecimal.valueOf`) with `HALF_EVEN` gives the same digits.
  `String.format("%.3f", 0.0625)` gives `0.063` where Python gives `0.062`: `java.util.Formatter`
  rounds half up on the shortest decimal form, so it also differs on values that are not exact
  ties, such as 4135 ms written as seconds (`4.13` in Python, `4.14` from `String.format`).
- The golden files hold values on which the usual mistakes differ, so the `:format` tests catch
  them: one fix with `accuracy_m` 4.25, `altitude_m` 18.25 and `speed_mps` 1.125 (written `4.2`,
  `18.2` and `1.12`), a ping that took 4135 ms (`4.13`) and a download of 20.0625 Mbit/s
  (`20.062`). `String.format`, `BigDecimal.valueOf`, `RoundingMode.HALF_UP` and `Math.round` each
  get at least one of them wrong.
- Never format with the default locale. A phone set to German writes `44,7`; in `traffic.csv`
  that crashes the report (`float("44,7")`), in `kpi.csv` it silently becomes -44 and 7.
- Never `Double.toString()`: it writes `1.0E-4` and drops trailing zeros.
- A value that rounds to zero is written `0.0`, never `-0.0`. (Python would print `-0.0` for a
  tiny negative; the golden files contain none, and `fieldtap validate` warns.)
- When Android gives an integer (RSRP, RSRQ, SINR, RSSI are all `int`), format the integer:
  `-84` becomes `-84.0`. No double is involved and no rounding can differ.
- `time_epoch` is Unix seconds with exactly three decimals. Build it from integer milliseconds,
  `"%d.%03d" % divmod(ms, 1000)`, never from a double.
- One value per field. Lists appear only in the text columns defined as lists, `bands` and
  `additional_plmns`, written as `a, b` (comma and space): `bands` in the order Android returns
  them, `additional_plmns` in ascending order. Such a field contains a comma, so it is quoted.

### Timestamps

Every column or key whose name ends in `_utc` holds exactly this 29-character form:

```
2026-09-10T14:30:00.400+00:00          yyyy-MM-ddTHH:mm:ss.SSS+00:00, always UTC
```

Kotlin: `DateTimeFormatter.ofPattern("yyyy-MM-dd'T'HH:mm:ss.SSSxxx").withZone(ZoneOffset.UTC)`.
The lower-case `xxx` prints `+00:00`; upper-case `XXX` prints `Z`. Python:
`when.astimezone(timezone.utc).isoformat(timespec="milliseconds")`, which is `session.iso()`.

| Rule | What breaks otherwise |
| --- | --- |
| Never a trailing `Z`. Never `Instant.toString()`, which writes `Z`, drops `.000` on whole seconds and can print nanoseconds. | `datetime.fromisoformat` rejects `Z` before Python 3.11. On Python 3.9 and 3.10 the track, events and traffic readers raise `ValueError`: crashes. This fieldtap maps `Z` to `+00:00` (`fieldtap.isotime.parse_iso`), so a current install survives, but older installs and other tools do not. `fieldtap validate` warns. |
| Never a time without an offset. | The report subtracts `started_utc` from event times. A naive `events.csv` time or a naive `started_utc` raises `TypeError: can't subtract offset-naive and offset-aware datetimes`: crashes. A naive `track.csv` time survives today's report, which never compares track times, but `fieldtap validate` still rejects it. |
| Milliseconds exactly three digits, offset written `+HH:MM`. | Python 3.9 and 3.10 accept only a 3- or 6-digit fraction and an `+HH:MM` offset; `.4` or `+0000` crashes the same readers as `Z`. |

Which instant a value carries. The measurement time, which is the wall clock at the answer minus
the sample's age, is carried by `time_epoch` in `kpi.csv` and `cellinfo.csv`, by the `time_utc` of
a `serving_cell` event (the first sample from the new cell), by `first_seen_utc` in `cells.csv`,
and by `start_utc` and `stop_utc` in `collection.gaps`. Every other value carries the wall clock
when the app observed it: `seen_utc` in `cellinfo.csv`, the other events (a `sampling_gap` event
is written when the gap ends), and a test's start in `traffic.csv`. A `track.csv` row carries the
fix's own time.

### session.json bytes

- UTF-8, no byte order mark, LF line endings, one LF after the closing brace.
- Two-space indent, one member per line, `"key": value` with one space after the colon, `,` at
  the end of every member but the last. An empty object is `{}` and an empty array `[]` on one
  line. Non-ASCII characters are written as UTF-8, not `\u` escapes, and `/` is not escaped.
- Keys in the order of the table in [session.json](#sessionjson).
- Integers without a decimal point; non-integers as the shortest decimal that reads back to the
  same double (`88.3`, `14.0`, `0.0`).
- Python reference: `json.dumps(meta, indent=2, ensure_ascii=False) + "\n"`.
- The CSVs must match the golden files byte for byte. If the Kotlin JSON serializer cannot
  produce this exact layout, compare `session.json` by parsed value and key order instead.

### Writing safely

| Rule | What breaks otherwise |
| --- | --- |
| CSVs are append-only, flushed every second, synced to disk every 5 s. | |
| When an interrupted session is closed on the next launch, cut every CSV back to the end of its last complete line (its last `\r\n`) before writing `stopped_utc`, which is the last heartbeat. | A half-written last row, such as `2026-09-10T14:32:00.0` alone, crashes the report in `track.csv` (`float(None)`); in `traffic.csv` it crashes on Python 3.9 and 3.10, and on later versions silently adds a failed test with no name. A row cut inside its last field still has every field: `kpi.csv` ending in `...,38.8895138,-7` puts a point far off the route and shrinks the map, silently. `fieldtap validate` rejects a row with the wrong number of fields in any session, and a last line without a line ending in an app session. |
| `session.json` is rewritten atomically: write `session.json.tmp`, sync, rename over the old file. | A torn `session.json` is not JSON: crashes. |

## Directory name

`<yyyyMMdd-HHmmss>_<slug>`, for example `20260910-143000_Mall-walk-north-path`.

- The time is `started_utc` in UTC, cut to the second, not rounded: 14:30:00.750 gives `143000`.
- The slug is `fieldtap.session.slugify(name)`:
  1. trim white space from both ends;
  2. replace every run of characters outside `A-Z a-z 0-9 . _ -` with one `-`;
  3. strip `-` from both ends;
  4. keep the first 48 characters (this can leave a trailing `-`);
  5. if nothing is left, use `session`.

  Python: `re.sub(r"[^A-Za-z0-9._-]+", "-", name.strip()).strip("-")[:48] or "session"`.
  Examples: `Mall walk (north path)` gives `Mall-walk-north-path`; `Café – lobby` gives
  `Caf-lobby`; three spaces give `session`.
- An existing directory is never reused.

What breaks otherwise: session lists (`fieldtap sessions`, the report index) sort directory
names newest first, so another form puts the session in the wrong place. `fieldtap validate`
warns when the name does not match `started_utc` and `name`.

Rules for `session.json`, and what breaks:

| Rule | What breaks otherwise |
| --- | --- |
| `transport`, `handset`, `device`, `modem`, `log_mask`, `files` and `summary` are objects, `{}` when empty, never `null`. | `summary`, `handset` or `files` as `null` crashes the report (`AttributeError: 'NoneType' object has no attribute 'get'`). The others survive today's report and session index, but other readers take them for objects. |
| `summary.plmns` is an object, never an array. `summary.messages`, `summary.client` and `summary.framing`, which the app does not write, are never `null`, and every `summary.messages` value is an integer, 0 or more. | An array in `plmns` crashes the report (`'list' object has no attribute 'keys'`); `messages: null`, or a string among its values, crashes it too. |
| `handset` values are strings. | A number in `manufacturer` or `model` crashes the report title. |
| `transport.transport` is `"android-api"`, never `"file"`. | `"file"` labels the whole report "SIMULATED (file replay)". | `started_utc` is present, in the timestamp form. | Missing: no duration, no charts, no event offsets. Without an offset: crashes (see Timestamps). |
| `capabilities.layer3` is `false`. | The report's signalling sections (Procedures, Call flow, handover and RRC tiles) depend on it together with `format` and `transport`. |
| `summary` never holds `modem_time_first_utc` or `modem_time_last_utc`. | The report takes the duration and the chart origin from them: a two-minute session can show an hour, silently. `fieldtap validate` rejects them. |
| For a session Android stopped, `stopped_utc` is the last heartbeat and equals the `time_utc` of the `session_interrupted` event. | The time of the next launch makes the report header show a duration of hours or days. `fieldtap validate` rejects a `stopped_utc` more than 1 s from that event's time (`events.interrupted_stop_tolerance_seconds`). |
| At most 16 MiB, with objects and arrays nested at most 32 levels deep (`session_json.max_bytes`, `session_json.max_depth`); the contract's own keys nest 4 deep. | A JSON reader can crash on deep nesting (`RecursionError`). `fieldtap validate` reads neither a larger nor a deeper file, and reports it as an error. |
| No key named `imei`, `imeisv`, `meid`, `imsi`, `iccid`, `msisdn`, `phone_number`, `line1_number`, `subscriber_id`, `sim_serial`, `serial`, `serial_number`, `android_id`, `advertising_id`, `tmsi`, `guti`, `supi`, `suci`, `ssid`, `bssid`, `mac`, `mac_address`, `ip` or `ip_address`, and no value that looks like an IMEI, IMSI or ICCID, anywhere. | A privacy breach in every uploaded copy. `fieldtap validate` rejects it (see [Identifiers](#identifiers)). |

## The CSV files

Each table lists the columns in header order. **Type** follows `columns.json`: timestamp (type
`utc`, the `*_utc` form), `integer`, `decimal N` (type `decimal`, exactly N decimals), `text`,
or a list of allowed values (type `enum`). **Blank** says when the field may be empty; "never"
columns are `required` in `columns.json`, and "always" columns are `always_blank` (they exist
for laptop sessions). Ranges are inclusive and are `min`/`max` or `range_by_rat` in
`columns.json`.

### kpi.csv

`frame,time_epoch,rat,meas_id,pci,rsrp_dbm,rsrq_db,sinr_db,comment,lat,lon`

One row per fresh serving-cell sample per RAT. The report draws the RSRP chart, the LTE RSRQ and
NR SINR chart, the averages in `summary.json` (`kpi.lte.rsrp_avg`, `kpi.nr.rsrp_avg`), the
"share below -105 dBm" tile and the route colours from it.

| Column | Type | Blank | Source and notes |
| --- | --- | --- | --- |
| `frame` | integer | always | Laptop sessions: the pcapng frame. |
| `time_epoch` | decimal 3 | never | When the modem measured the sample (wall clock minus age), Unix seconds. 946684800.000–4102444800.000. |
| `rat` | `lte`, `nr` | never | |
| `meas_id` | integer | always | Laptop sessions: the RRC measId. |
| `pci` | integer | if unknown | `CellIdentityLte.getPci()` 0–503; `CellIdentityNr.getPci()` 0–1007. |
| `rsrp_dbm` | decimal 1 | if unknown | LTE `CellSignalStrengthLte.getRsrp()`, -156.0 to -43.0. NR `CellSignalStrengthNr.getSsRsrp()`, -156.0 to -29.0. |
| `rsrq_db` | decimal 1 | if unknown | LTE `getRsrq()`, -34.0 to 3.0. NR `getSsRsrq()`, -43.0 to 20.5. |
| `sinr_db` | decimal 1 | if unknown | LTE `getRssnr()`, -23.0 to 40.0. NR `getSsSinr()`, -23.0 to 40.5. |
| `comment` | text | never | `android-api age_ms=<age> src=<request or push>`: the sample's age in milliseconds when the app received it, and whether `requestCellInfoUpdate` or `CellInfoListener` delivered it. |
| `lat` | decimal 7 | when no fix is within 5 s | -90 to 90. |
| `lon` | decimal 7 | exactly when `lat` is | -180 to 180. |

| Rule | What breaks otherwise |
| --- | --- |
| Only fresh samples: a cell-info answer whose modem timestamp (`CellInfo.getTimestampMillis()`) the app has not seen before. A repeat goes to `cellinfo.csv` with `stale` 1. | A cached repeat logged as a measurement inflates the sample count and flattens the chart. `fieldtap validate` warns when a row repeats the `rat` and `time_epoch` of one of the 8 rows of that RAT before it. |
| Only serving cells: the cell reported as primary serving, and in NSA also the NR cell reported as secondary serving. NSA gives an `lte` and an `nr` row with the same `time_epoch`. | A neighbour row silently mixes into the serving-cell averages. |
| A sample at most 2500 ms old while Android's 2 s interval applies, at most 11000 ms otherwise (`kpi.max_age_ms_short_interval`, `kpi.max_age_ms`). | An old sample lands at the wrong place on the route. `fieldtap validate` warns above 11000. |
| `rat` is `lte` or `nr`. | Any other value: the row is silently ignored. |
| One number per field. | Laptop `kpi.csv` files can hold comma-separated lists; the report takes the first number, so a list silently loses the rest. `fieldtap validate` rejects lists in an app session. |
| Values inside the ranges; Android's unavailable written blank. | Out-of-range values skew the averages and are clipped on the chart, silently. |

### Location precision

`privacy.location_precision` describes the positions in the files it sits beside. The phone
keeps a full-precision local copy and applies the precision when it builds the export or upload
copy, rewriting `privacy.location_precision` in that copy.

| Precision | `track.csv` | `lat`, `lon` in `kpi.csv` and `cellinfo.csv` |
| --- | --- | --- |
| `full` | as measured | as measured |
| `approx_110m` | every value rounded to 3 decimals, still written with 7: `38.8895123` becomes `38.8900000` | rounded the same way |
| `none` | left out | blank |

Rounding: `BigDecimal(v).setScale(3, RoundingMode.HALF_EVEN)`, then written with 7 decimals.
`fieldtap validate` rejects a position more precise than the declared precision, and any
position at `none`.

## The upload bundle

The export and upload file is `<session directory name>.zip`, for example
`20260910-143000_Mall-walk-north-path.zip`, holding the upload copy of the session (location
precision applied, `privacy.location_precision` set to match). It is sent with its SHA-256.

| Rule | What happens otherwise |
| --- | --- |
| Flat: every entry is a bare file name. No directories and no directory entries. | Rejected. |
| Only `session.json`, `kpi.csv`, `track.csv`, `events.csv`, `traffic.csv`, `cells.csv` and `cellinfo.csv`, each at most once, spelled exactly so. `session.json` is required. Never `summary.json`, `report.html` or `index.html`. | Rejected, including a second copy of a name or a name that differs only in case. |
| No `..` segment, no leading `/`, no drive letter (`C:`), no backslash, no control character, no symbolic link. | Rejected: these are how an archive writes outside the directory it is extracted into. |
| Compression stored (method 0) or deflate (method 8); not encrypted; not zip64; one part. `java.util.zip.ZipOutputStream` with `ZipEntry(name)` and `DEFLATED` produces this. | Rejected. |
| The zip file is at most 52 428 800 bytes (50 MiB). | Rejected before it is opened. |
| The entries total at most 209 715 200 bytes (200 MiB) uncompressed. | Rejected. The check counts bytes while decompressing and stops at the limit, so a header that understates a size gains nothing; such an entry also fails its CRC. |
| The SHA-256 of the zip file, 64 lower-case hex digits, travels with the upload. | The server refuses a bundle whose hash differs. |

Server side, in order: download, compare `fieldtap.contract.sha256_file(zip)` with the hash sent,
run `fieldtap.contract.validate_bundle(zip)` (nothing is extracted), extract into an empty
directory named after the zip, run `validate_session(dir, upload=True)`, then
`report.build(dir, tshark=None, rebuild=False)`.

## Identifiers

No file ever holds an IMEI, IMSI, ICCID, MSISDN or phone number, TMSI or GUTI, serial number,
`ANDROID_ID`, advertising ID, adb serial, Wi-Fi name, MAC address or IP address. The app does not
collect them in the first place. As a safety net, `fieldtap validate` searches every key and
value of `session.json` and every text column of every CSV, and rejects:

| Looks like | Pattern |
| --- | --- |
| an IMEI | a run of exactly 15 digits, with no letter or digit on either side, that passes the Luhn check |
| an IMSI | a run of 14 or 15 digits starting with 2 to 7 (a mobile country code) |
| an ICCID | a run of 19 or 20 digits starting with 89, optionally followed by `F` |
| a forbidden key | in an app session, any key listed under [session.json](#sessionjson) |

A long digit run typed into a note is rejected too, so keep phone numbers and serials out of
notes and marker text.

## fieldtap validate

```
fieldtap validate <session directory> [--upload] [--json]
fieldtap validate <bundle>.zip [--json]
```

It prints one problem per line, `<severity> <file>[:<line>]: <message>`, for example

```
error kpi.csv:12: rsrp_dbm -184.0 is outside -156.0..-43.0 dBm for lte
warning events.csv:4: time_utc '2026-09-10T14:30:45.200Z' ends in Z: ...
```

`line` is the physical line, the header being line 1; `file` is `.` for the directory or the
bundle itself. A count goes to standard error. `--json` prints
`{"target", "kind", "format", "errors", "warnings", "problems": [{"severity", "file", "line", "message"}]}`
instead. `--upload` also requires that the directory holds nothing but the seven files, at most
209 715 200 bytes of them together.

Exit status: **0** no errors (warnings allowed), **1** at least one error, **2** the target is
not a directory or a `.zip`, or the arguments are wrong.

From Python: `fieldtap.contract.validate_session(path, upload=False)` and
`validate_bundle(zip_path)` return lists of `Problem(severity, file, line, message)`;
`contract.errors(problems)` keeps the errors. Problems are returned, never raised.

**How strict.** An app session is checked against every rule here that can be seen in its files;
rules about how the app behaves (only serving cells, flushing every second, the atomic rename)
cannot be. A session is an app session when `format` is `fieldtap-session/1`, when
`transport.transport` is `android-api`, or when it has any of `capabilities`, `collection` or
`privacy` (`session_json.app_only_keys`), which the laptop tool never writes. A misspelt or
missing `format` or `transport.transport` is then an error, never a switch to the lenient checks.

- **Errors** are what crashes or silently corrupts the report, what breaches privacy, and what
  breaks a hard rule: a header, a required value, a type, an allowed value, a range.
- **Warnings** are what the report survives but a correct writer never produces: a trailing `Z`,
  a timestamp or number that reads correctly but is not in the canonical form, lines not ending
  in CR LF, a row that runs over two lines, an unknown event kind, a missing file.

Any other session, such as the laptop tool's, which have none of those keys, gets only the checks
whose failure breaks the report, plus timestamps, headers, identifiers and, when
`capabilities.layer3` is false, signalling kinds. There a 0,0 fix, fixes out of time order and a
last line without a line ending are warnings. `fieldtap demo` output passes with two warnings: no
`format` key, and transport `file`. A rule that fires on many rows of a file is shown five times
and then counted.

**What it costs.** `fieldtap validate` reads each CSV one line at a time, so its memory stays
small whatever the size of the file; its time grows with the number of rows. On the PC it was
measured on, a 200 MB `cellinfo.csv` took 44 s and the process stayed under 30 MB. It stops reading a
CSV at a line longer than 1 048 576 characters (`encoding.csv_max_line_chars`), reads no
`session.json` larger than 16 MiB or nested deeper than 32 levels, and with `--upload` checks
nothing else once the seven files total more than 209 715 200 bytes. Each of these is an error.

### Known breakages at a glance

| Violation | `fieldtap report` | `fieldtap validate` |
| --- | --- | --- |
| A `*_utc` value ending in `Z` | Crashes on Python 3.9 and 3.10 with a fieldtap older than `isotime.parse_iso` | warning |
| A `*_utc` value with no offset | Crashes (`events.csv`, `started_utc`) | error |

| A last row cut inside its last field, with every field still there | A point silently far off the route | error in an app session, warning otherwise |
| A 0,0 fix, or fixes out of time order | Route and distance silently wrong | error in an app session, warning otherwise |
| `n/a` or a decimal comma in `traffic.csv` | Crashes | error |

## Reading columns.json

The top-level keys, in file order:

| Key | Holds |
| --- | --- |
| `format`, `schema_version` | `"fieldtap-session/1"` and `1`. |
| `encoding` | `charset`, `byte_order_mark`, `csv_line_terminator` (`"\r\n"`), `csv_delimiter`, `csv_quote`, `csv_quoting` (`"minimal"`), `csv_quote_if_contains` (comma, `"`, CR, LF), `csv_blank` (`""`), `csv_max_line_chars`, `text_line_breaks` (`"replace_with_space"`), `number_rounding` (`"half_even_exact_binary"`: `"%.Nf"` in Python, `BigDecimal(v).setScale(N, RoundingMode.HALF_EVEN)` in Kotlin), `number_digits` (`"ascii"`), `decimal_separator` (`"."`), `negative_zero` (`false`), `json_line_terminator`, `json_indent`, `json_ascii_only`. |
| `patterns` | How every `pattern` matches: `match` is `"full"`, the whole value (`re.fullmatch` in Python, `Regex(pattern).matches(value)` in Kotlin, never a search); `syntax` says which constructs they use, so that Python, the JVM and Android's ICU regex agree; `search_patterns` names the two patterns that are searched for inside a value instead; `python_only_patterns` the one Kotlin never needs. |
| `timestamps` | `utc_pattern` (the regular expression every `*_utc` value matches), `utc_kotlin_pattern`, `utc_example`, `python_portable_pattern` (what Python 3.9 can read), `time_epoch_decimals`. |
| `android_unavailable` | `2147483647`. |
| `directory` | The name pattern, the time formats and the slug rules. |
| `files` | The seven file names. |
| `report_outputs` | The files the app never writes. |
| `session_json` | `never_null_objects`, the transport values, `app_only_keys`, `laptop_summary_keys`, `handset_keys`, `location_precisions`, `approx_110m_decimals`, `forbidden_keys`, `max_bytes`, `max_depth`, and `fields`. |
| `csv` | One object per CSV file. |
| `events` | `severities`, `app_kinds` (kind, allowed `rat`, allowed `severity`, whether `pci` and `arfcn` are filled), `signalling_kinds`, `signalling_kind_prefixes`, `interrupted_stop_tolerance_seconds`. |
| `traffic_tests` | The `app` and `laptop` test names. |
| `kpi` | `max_age_ms`, `max_age_ms_short_interval`, `gps_match_seconds`, `time_window_slack_seconds`, `comment_pattern`. |
| `identifiers` | The digit-run regular expression and the IMEI, IMSI and ICCID rules. |
| `upload_bundle` | `name`, `file_names`, `required`, `max_compressed_bytes`, `max_uncompressed_bytes`, `compression_methods`, `zip64`, `hash`. |

A `csv` entry has `name`; `presence` (`always`, or `unless_precision_none` for `track.csv`);
`header`, the ordered column names; `min_columns`, how many leading columns an older laptop file
may stop after (an app session writes the whole `header`); and `columns`, one object per column
with every key present:

| Key | Meaning |
| --- | --- |
| `name` | The header name. |
| `type` | `utc`, `integer`, `decimal`, `enum` or `text`. |
| `format` | The Python printf reference for the digits of an `integer` or `decimal` (`"%d"`, `"%.7f"`), otherwise `null`. Never a `java.util.Formatter` format: see [Numbers](#numbers). |
| `decimals` | Digits after the point for `decimal`, otherwise `null`. |
| `required` | Never blank in an app session. |
| `always_blank` | Always blank in an app session. |
| `min`, `max` | Inclusive bounds, or `null`. |
| `range_by_rat` | `{"lte": [min, max], "nr": [min, max]}`, which replaces `min` and `max` for rows of that `rat`; or `null`. |
| `unit` | For example `"dBm"`, or `null`. |
| `values` | The allowed strings for `enum`, otherwise `null`. |
| `pattern` | A regular expression the whole `text` value matches (see `patterns`), or `null`. |
| `list_allowed` | Laptop sessions may hold comma-separated numbers here; an app session never does. |
| `list_separator`, `list_order` | For a text list (`bands`, `additional_plmns`): `", "`, and `"ascending"` or `"as_reported"`. Otherwise `null`. |
| `breaks_report` | An invalid value crashes or silently corrupts the report, so `fieldtap validate` checks it in every session, not only app sessions. |

A `session_json.fields` entry has `path` (dotted; `name[]` means every item of that array),
`type` (`string`, `integer`, `number`, `boolean`, `object`, `array` or `utc`), `required`,
`nullable`, `values`, `pattern`, `min`, `max` and `decimals`: for a `number`, how many decimals it
is rounded to (half-even on the exact binary value, as Python's `round`) before it is written as
the shortest decimal that reads back to the same double; otherwise `null`.

## Keeping both sides honest

- To change the format, change the Python constant (`gps.COLUMNS`, `events.COLUMNS`,
  `traffic.COLUMNS`, `kpi.SESSION_COLUMNS`, `session.CELLS_COLUMNS`, `scan.COLUMNS`) or the spec
  in `fieldtap/contract.py`; regenerate the schema with
  `python -c "from fieldtap import contract; contract.write_schema('schema/columns.json')"`;
  regenerate the golden session with `python tests/fixtures/make_android_session.py`; update this
  document. A change an existing reader would misread needs a new format name.
- `tests/test_android_session.py` fails when `columns.json` and the Python constants disagree,
  when the generator no longer reproduces the committed fixture byte for byte, when the report no
  longer renders it, or when `validate_session` stops catching one of the broken cases.
- `.gitattributes` marks `tests/fixtures/android_session/**` as `-text`, so `core.autocrlf` never
  rewrites the golden bytes on checkout. `git check-attr text <a fixture file>` prints
  `text: unset`.
- The app's `:format` tests, in `android/`, write the same session from the same inputs and
  compare it with the fixture. CI runs them with the Python tests, and its emulator job checks a
  session recorded end to end with `fieldtap validate` before rendering it with `fieldtap report`.

## Where this differs from the plan

The short description in `docs/APP-PLAN.md` came first. Where they differ, this document,
`columns.json` and the fixture win:

- **CSV line endings are CR LF, not LF.** fieldtap's writers are Python's `csv` module, which
  writes `\r\n` on every platform, and the golden files are made by them. Switching the Python
  writers to LF would also need extra quoting: with an LF terminator Python's `csv` module leaves
  a field containing a lone CR unquoted.
- **The bundle limit is 50 MiB, 52 428 800 bytes**, where the plan says 50 MB. `validate_bundle`
  refuses a zip of 52 428 801 bytes or more.
- `cells.csv` is rewritten when the session closes, because its counts are known only then.
- A change of only the NSA NR leg is not a `serving_cell` event, so `cell_changes` counts anchor
  changes as it does for laptop sessions.
